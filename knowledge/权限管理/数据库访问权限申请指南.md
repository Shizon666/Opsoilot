# 数据库访问权限申请指南

> 状态：大纲（正文待写）

## 1. 文档目的

- `resource_type=DATABASE` 申请规则与级别选择
- 医疗业务相关数据：公司内部加严；生产 / ADMIN → `human`
- 不写 HIPAA 等外部法规名称

## 2. 适用范围

- 【待写】公司托管业务库、分析库、直播/内容相关库
- 【待写】连接失败时区分：无权限 vs VPN/账号问题

## 3. 权限级别（大纲）

| permission_level | 含义（待写） | 风险提示 |
|------------------|--------------|----------|
| READ | 查询为主 | 仍禁滥用导出 |
| DEVELOPER | 开发/测试变更类 | 生产默认加严 |
| ADMIN | 高权限 | 必须人工 |

## 4. 流程（大纲）

1. 确认库名、环境、用途  
2. 选最低必要级别与 reason  
3. Permission → Approval（高风险按 H 检查）  
4. 开通后仅限申请用途

## 5. 限制条件（大纲）

- 禁止共享库账号、聊天发连接串/密码
- 禁止以催促跳过 Approval
- 禁止用 Ticket 代替权限申请
- 内部保密与最小化使用要求（公司制度表述）

## 6. 何时转人工（大纲）

- 生产访问、ADMIN
- 用途不清、角色与资源不匹配
- 跨部门批量要数

## 7. 示例问题

1. 查课程相关表申请 READ 还是 DEVELOPER？
2. 生产只读要特殊说明吗？
3. VPN 通了连不上库怎么判断？
4. 临时救急能否先给 ADMIN？
5. reason 最少要写哪些信息？
