# 开发环境权限申请指南

> 状态：大纲（正文待写）

## 1. 文档目的

- `resource_type=DEV_ENV` 申请规则
- 澄清：环境权限 ≠ GitLab ≠ Database（常需分别申请）

## 2. 适用范围

- 【待写】公司统一开发/联调/预发环境
- 【待写】个人装开发工具 → Ticket / 常见问题指南
- 【待写】环境宕机报障 → Ticket

## 3. 权限级别（大纲）

| permission_level | 含义（待写） | 典型用途 |
|------------------|--------------|----------|
| READ | 只读角色/只读控制台 | 验收查阅 |
| DEVELOPER | 日常联调部署 | 研发/测试 |
| ADMIN | 环境管理 | 环境负责人 |

## 4. 流程（大纲）

1. 确认环境 `resource_name` 与级别  
2. 前置：账号可用；必要时 VPN（见常见问题指南）  
3. Permission → Approval  
4. 验证登录；缺仓库或库权限则另开 Permission

## 5. 限制条件（大纲）

- 不得将开发环境当生产或导入不必要的真实敏感全量数据（内部要求）
- 不得账号转让
- 不得合并成「一张工单搞定所有权限」

## 6. 入口对照（大纲）

| 诉求 | intent | API |
|------|--------|-----|
| 环境角色 | permission | DEV_ENV |
| 拉代码 | permission | GITLAB |
| 连开发库 | permission | DATABASE |
| VPN/登录 | ticket / answer | Ticket |
| 环境故障 | ticket | Ticket |

## 7. 示例问题

1. 新员工开通开发环境走权限还是工单？
2. 有仓库权限但进不了联调环境？
3. 预发和开发要申请两次吗？
4. 测试是否需要 ADMIN？
5. 环境打不开先申请还是先报障？
