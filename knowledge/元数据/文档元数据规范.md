# 知识文档元数据规范（Phase 10 / 中文制度语料）

> 版本：v1.2  
> 适用范围：`knowledge/` 下 **Phase 10** 中文制度与员工自助类业务 MD（不含本文件与 `README.md`）  
> **不适用：** V1 运维知识库 `knowledge/ops/`（含 `catalog.yaml` / `raw/**`）  
> V1 ops 元数据与建设规范真源：[`../ops/STANDARDS.md`](../ops/STANDARDS.md)  
> 状态：Phase 10 语料仍保留文件时生效；**不得**将本规范字段（`related_intent` / `rag.employee` 等）套用于 ops catalog  
> 说明：磁盘路径为中文企业命名；**YAML 字段名保持英文**。

## 1. Front matter 位置

每个业务 Markdown 文件开头必须为 YAML front matter（`---` 包裹），其后为大纲或正文。

## 2. 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `doc_id` | string | 是 | 稳定文档编号，如 `XXY-IT-CAT-001`（RAG/引用优先用此 ID） |
| `title` | string | 是 | 中文标题（可与文件名一致） |
| `version` | string | 是 | 语义化版本；大纲阶段用 `0.1.0-outline` |
| `status` | enum | 是 | `outline` \| `draft` \| `active` \| `archived` |
| `company` | string | 是 | 固定：`北京小小医信息科技有限公司` |
| `owner` | string | 是 | 如 `信息技术部` |
| `category` | enum | 是 | 见 §3（英文字面量） |
| `visibility` | enum | 是 | 见 §4 |
| `related_intent` | string[] | 是 | 见 §5；至少 1 个 |
| `rag` | object | 是 | 见 §6 |
| `audience` | string[] | 是 | `employee` \| `it_support` \| `admin` |
| `related_api` | string[] | 否 | 如 `POST /tickets`、`POST /permissions` |
| `resource_type` | enum | 条件 | access 指南必填：`GITLAB` \| `DATABASE` \| `DEV_ENV` |
| `supersedes` | string | 否 | 被替代的旧 `doc_id` |
| `updated` | date | 是 | `YYYY-MM-DD` |

非 MD 资产（如 `权限与审批关系矩阵.xlsx`）用同目录 `*.meta.yaml` 旁路描述。

## 3. `category`（分类，英文字段值）

| 值 | 含义 | 知识库目录 |
|----|------|------------|
| `catalog` | 服务目录与总路由 | `knowledge/服务目录/` |
| `policies` | 制度与规范（含数据安全须知） | `knowledge/制度规范/`、`knowledge/数据安全/` |
| `access` | 权限申请细则 / 矩阵 | `knowledge/权限管理/` |
| `howto` | 员工自助与建单边界 | `knowledge/常见问题/`、`knowledge/账号登录/`、`knowledge/VPN与远程办公/`、`knowledge/办公与直播设备/`、`knowledge/软件安装/` |
| `runbooks` | Support 内部作业 | `knowledge/作业手册/` |

> Agent/RAG 入库：扫描 `knowledge/` 下业务 MD，读 front matter；**同一 `category` 可对应多个中文目录**。不要写死旧英文路径或「仅常见问题」单一目录。


## 4. `visibility`（可见性）

| 值 | 含义 | Agent 默认行为 |
|----|------|----------------|
| `PUBLIC` | 全员可读 | 可进入 Employee 会话检索 |
| `INTERNAL` | 仅 IT Support / Admin | **不进入 Employee RAG**；仅 Support/Admin 检索通道 |

第一阶段约定：

- `作业手册/IT-Support内部处理规范.md` → `INTERNAL`
- `权限管理/权限与审批关系矩阵.xlsx` → `INTERNAL`
- 其余核心 MD → `PUBLIC`

## 5. `related_intent`（业务意图）

| 值 | 含义 | 典型系统动作 |
|----|------|--------------|
| `answer` | 可直接回答，无需写操作 | 仅回复 |
| `ticket` | 应创建 / 引导 Ticket | `POST /tickets` 等 |
| `permission` | 应发起 Permission | `POST /permissions` → Approval |
| `human` | 必须转人工 | 提示 Support；高风险不自动 approve |

## 6. `rag`（检索策略）

```yaml
rag:
  employee: true   # 是否进入 Employee RAG 集合
  support: true    # 是否进入 Support/Admin RAG 集合
  primary: true    # 是否为该类意图的主召回文档（矩阵表为 false）
```

规则：

1. `visibility: INTERNAL` ⇒ `rag.employee` **必须为** `false`
2. 权限矩阵 ⇒ `rag.employee: false`，`rag.support: false` 或仅人工查阅；`primary: false`（**非 RAG 主数据**）
3. `rag.primary: false` 的资产不作为向量库主入库对象
4. 路径变更不影响入库：以 `doc_id` + `rag.*` 为准

## 7. 示例（完整）

```yaml
---
doc_id: XXY-IT-CAT-001
title: IT 服务目录与入口指引
version: 0.1.0-outline
status: outline
company: 北京小小医信息科技有限公司
owner: 信息技术部
category: catalog
visibility: PUBLIC
related_intent: [answer, ticket, permission, human]
rag:
  employee: true
  support: true
  primary: true
audience: [employee, it_support, admin]
related_api: []
updated: 2026-10-01
---
```

对应路径：`knowledge/服务目录/IT服务目录与入口指引.md`

## 8. 校验清单（落盘/入库前）

- [ ] front matter 可被 YAML 解析；**字段名为英文**
- [ ] `category` / `visibility` / `related_intent` 取值合法
- [ ] INTERNAL 文档未标记 `rag.employee: true`
- [ ] 非主数据（矩阵）`rag.primary: false`
- [ ] access 指南含 `resource_type`
- [ ] 文档内「相关文档」链接使用现行中文路径
