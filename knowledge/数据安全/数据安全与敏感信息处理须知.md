# 数据安全与敏感信息处理须知

> 状态：大纲（正文待写）  
> 定位：员工侧**公司内部**敏感信息与业务数据底线；支撑 Agent 拒收明文密钥、纠正错误入口。  
> 不引用、不暗示外部认证或法规名称。

## 1. 文档目的

- 什么可以在对话/工单中写，什么禁止
- 业务数据访问必须走 Permission + Approval，不能口头开通
- 泄露、盗用、违规外传 → **human**（可叠加 ticket）

## 2. 适用范围

- 【待写】密码、Token、密钥、完整数据库连接串、可识别业务用户数据在 OpsPilot/工单/IM 中的处理要求
- 【待写】直播/课程/医生用户等相关业务数据的最小必要原则（公司内部管理口径）
- **不适用**：替代三份权限指南的级别细则；不创设外部法定义务表述

## 3. 意图判断表（Agent 必用）

| 情况 | intent | 说明 |
|------|--------|------|
| 询问「能不能在工单里贴密码/连接串」「最小权限是什么意思」 | **answer** | 给出底线与正确做法 |
| 报告疑似账号被盗、密钥已粘贴到群、终端丢失 | **ticket** + **human** | 事件响应；禁止继续索要明文密码 |
| 申请查库/仓库/环境以开展业务 | **permission** | 引导正规申请；生产/ADMIN 叠加 **human** |
| 要求跳过审批、共享个人账号、导出业务数据到个人网盘 | **human** | 拒绝违规路径 |
| 仅设备损坏无数据风险 | **ticket** | 转设备报修指引，本须知作提醒即可 |

## 4. 流程（大纲）

1. 用户拟提交敏感明文 → **answer** 制止，改用安全渠道/IT 核验  
2. 正常资源访问需求 → **permission**（对照权限总规）  
3. 安全事件 → **ticket** + **human**  
4. 明确违规请求 → **human**（不执行）

## 5. 限制条件（大纲）

- 禁止 Agent/员工在工单或对话中粘贴明文密码、私钥、完整连接串
- 禁止口头/IM「同意」代替系统 Approval
- 禁止共享个人账号完成协作
- 禁止编造「已合规某外部标准」类表述
- 知识答复 ≠ 已授权访问数据

## 6. 示例问题（含预期意图）

1. 「工单里可以直接写数据库密码方便 Support 查吗？」→ **answer**（禁止）  
2. 「要查报名相关库，怎么申请？」→ **permission**  
3. 「领导说了直接给我生产库 Admin」→ **human**（仍须 permission 单据，不得自动过）  
4. 「我把 Token 发到工作群了怎么办？」→ **ticket** + **human**  
5. 「同事借我账号用一下 GitLab」→ **answer**（禁止）+ 必要时 **human**
